# Спецификация: Telegram-бот для заработка звёзд (рефералы + задания)

Дата: 2026-09-12
Статус: на ревью

## 1. Цель

Telegram-бот на Python + aiogram + SQLite, в котором пользователь зарабатывает
Telegram Stars за приглашённых друзей и выполнение заданий, а затем выводит их в
виде обычных (не NFT) Telegram-подарков. Выплаты подтверждает администратор
вручную через специальный чат заявок.

## 2. Стек и общая архитектура

- **Python 3.11+**, **aiogram 3.x**, long polling.
- **SQLAlchemy 2.0 (async) + aiosqlite**, файл БД `data/bot.db` (сохраняется
  между перезапусками).
- **aiohttp** — HTTP-сервер для интеграции с партнёрскими ботами
  (`POST /partner/confirm`), защищён API-ключом. Работает в том же asyncio-цикле.
- **python-dotenv** — конфигурация из `.env`.
- Баланс хранится **целым числом в десятых долях звезды** (tenths):
  `0.5★ = 5`, `3★ = 30`, `15★ = 150`. Исключает ошибки округления float.
- Вся логика — модульная: роутеры по доменам, сервисный слой, слой БД,
  middleware проверки обязательных подписок.
- Middleware **проверяет подписки вживую** (`getChatMember`) на каждое действие,
  а не только по кэшу `subscribed` — чтобы новые спонсоры, добавленные админом,
  сразу становились обязательными для всех.

## 3. Модель данных (SQLite)

### users
| поле | тип | описание |
|------|-----|----------|
| id | BigInteger PK | Telegram user id |
| username | String, nullable | текущий @username |
| first_name | String, nullable | имя |
| referred_by | BigInteger, nullable | id пригласившего |
| referral_credited | Boolean, default false | начислены ли 3★ пригласившему |
| balance_tenths | Integer, default 0 | текущий баланс |
| total_earned_tenths | Integer, default 0 | всего заработано |
| total_withdrawn_tenths | Integer, default 0 | всего выведено |
| subscribed | Boolean, default false | кэш прохождения спонсоров |
| is_blocked | Boolean, default false | заблокировал бота |
| created_at | DateTime | дата регистрации |

### sponsors (обязательные подписки)
id, type (`channel` | `bot`), subtype (`public_channel` | `chat` |
`private_request` — только для `channel`), title, url, chat_id (для channel),
active, expires_at (nullable — срок действия), max_completions (0 = без лимита),
partner_id (FK→partners, nullable — партнёр, чей бот подтверждает прохождение),
created_at.

### tasks (одноразовые задания, +0.5★)
id, type (`channel` | `bot`), title, url, chat_id, reward_tenths (default 5),
active, partner_id (FK→partners, nullable — партнёр, чей бот подтверждает
выполнение), created_at.

### partners
id, name, api_key (уникальный), active, created_at. Партнёрские ключи
создаются и просматриваются в админ-панели.

### settings
key (PK), value (nullable). Произвольные настройки бота, например базовый
адрес партнёрского API.

### user_tasks
id, user_id FK, task_id FK, completed_at. Уникальная пара (user_id, task_id) —
задание выполняется **один раз** на пользователя.

### withdrawals
id, user_id FK, gift_id, gift_name, gift_stars, username_to, status
(`pending` | `paid`), admin_chat_id, admin_msg_id, created_at, paid_at.

### broadcasts
id, text, media_file_id (nullable), sent_count, failed_count, created_at.

### promo_codes / promo_uses
Промокоды: `promo_codes` (id, code уникальный, stars, max_uses, used_count,
active, created_at) и `promo_uses` (id, user_id FK, promo_id FK, used_at;
уникальная пара user_id+promo_id). Пользователь активирует код кнопкой в меню,
звёзды начисляются один раз; лимит использований `max_uses` (0 = без лимита).

### gifts
Фиксированный список в коде (`utils/gifts.py`), сидируется в БД: id, name,
stars (15–100), emoji. Пример: `Медвежонок — 15★`, `Сердце — 25★`, … до 100★.

### Правила уникальности
- **Один друг = один раз.** Повторный переход по реферальной ссылке того же
  пользователя не создаёт новую запись и не начисляет звёзды. Начисление
  происходит один раз — через флаг `referral_credited`.
- **Один спонсор = один раз** в списке обязательных (уникальность chat_id/url
  при добавлении).
- **Одно задание = один раз** на пользователя (unique user_id+task_id).

## 4. Пользовательские сценарии

### 4.1 Первый вход и реферал
1. Пользователь переходит по `/start` или `/start ref_<id>`.
2. Бот создаёт запись (если нет), сохраняет `referred_by` (только если это
   новый пользователь; повторно реферера не меняем и не дублируем).
3. Проверяются обязательные спонсоры. Пока не пройдены все — доступно только
   окно «Подпишитесь на спонсоров» с кнопкой «✅ Проверить подписку».
4. Когда **приглашённый друг** проходит всех обязательных спонсоров:
   - если у него есть `referred_by`, и `referral_credited = false` —
     пригласившему начисляется **3★**, флаг ставится `true`, пригласившему
     уходит уведомление.
   - друг помечается `subscribed = true` и получает доступ в меню.

### 4.2 Главное меню
Inline-клавиатура. На каждом подэкране есть кнопка **«⬅️ Назад»** / **«🏠 Меню»**
для возврата в главное меню.

Кнопки:
1. **👤 Профиль** — сколько друзей приглашено, накоплено звёзд, выведено,
   текущий баланс, реферальная ссылка.
2. **📖 Инструкция** — подробный гайд «как заработать звёзды» + снизу кнопка
   **Поддержка** (URL из `.env`, открывает профиль поддержки).
3. **📋 Задания** — показывает, сколько заданий доступно; выдаёт одно задание.
4. **💸 Вывод звёзд** — вывод заработанных звёзд подарком.
5. **💰 Заработать звёзды** — текст (приглашай друзей по реф-ссылке, оставь
   ссылку в профиле и т.д.) + реферальная ссылка и кнопка «Поделиться».

### 4.3 Задания
- Доступные задания = активные `tasks`, не выполненные этим пользователем.
- Выдаётся одно задание: текст/ссылка + кнопки **«✅ Проверить»** и
  **«⏭ Пропустить»** (+ «⬅️ Назад»).
- **Каналы:** «Проверить» → `getChatMember`; при успехе +0.5★ (одноразово).
- **Боты:** «Проверить» → бот сообщает «выполните старт у партнёра»; начисление
  происходит после подтверждения от партнёрского бота (см. §6).
- **Пропустить** — бот выдаёт следующее доступное задание; если их нет —
  сообщение «Пока нет доступных заданий».
- Задания одноразовые: после начисления больше не показываются.

### 4.4 Вывод звёзд
1. Пользователь выбирает подарок из фиксированного списка (15–100★).
   Подарки дороже текущего баланса недоступны.
2. Бот просит ввести **username**, куда выводить звёзды (валидация формата,
   без `@`/с `@`).
3. Бот отправляет заявку в **чат админов** (`ADMIN_CHAT_ID`):
   - текст: подарок, цена в ★, заказчик (имя, @username, id), куда выводить;
   - кнопка **«👤 Профиль заказчика»** — URL `https://t.me/<username>`;
   - кнопка **«✅ Выплачено»** — callback.
4. При нажатии «Выплачено» (только админ):
   - заявка → `status = paid`, `paid_at = now`;
   - сообщение в админ-чате редактируется, статус меняется на «✅ Выплачено»;
   - баланс списывается, `total_withdrawn_tenths` растёт;
   - пользователю приходит уведомление «Админ отправил вам подарок 🎁».
5. Баланс списывается в момент подтверждения (не при создании заявки), чтобы
   избежать «зависших» списаний. Повторный callback защищён проверкой статуса.

## 5. Админ-панель (`/admin`)

Доступ только для ID из `ADMIN_IDS`. Разделы:

- **Спонсоры (обязательные):** добавить, удалить, список. Обязательными могут
  быть и **подписка на канал**, и **старт в боте** (`type = channel | bot`).
  - **Добавление канала по ссылке:** админ отправляет боту ссылку на канал
    (`https://t.me/<username>`, `t.me/<username>` или `@username`, либо id
    `-100...`). Бот через `getChat`/`getChatMember` проверяет, что **он сам
    является администратором** в этом канале. Если да — канал добавляется в
    обязательные подписки (сохраняются `chat_id`, `title`, `url`). Если бот не
    админ — понятная ошибка «бот не администратор этого канала, добавьте его и
    попробуйте снова». Запись по тому же `chat_id` повторно не создаётся.
  - Добавление бота-спонсора: по ссылке `t.me/<bot_username>`.
- **Задания:** добавить (FSM: тип → ссылка/chat_id → название → награда),
  удалить, список.
- **Партнёры:** добавить, удалить, посмотреть API-ключ. Ключи хранятся в
  таблице `partners`; боты-спонсоры и боты-задания привязываются к партнёру.
- **Промокоды:** раздел со списком (`promo_codes`), создание (FSM: код → звёзды
  → лимит) и удаление. Пользовательская кнопка «🎟 Промокод» активирует код.
- **Настройки:** базовый адрес партнёрского API и прочие параметры
  (таблица `settings`).
- **Рассылка:** FSM ввода текста (опц. медиа) → отправка всем `is_blocked=false`,
  учёт успешных/неуспешных, сохранение в `broadcasts`.
- **Статистика** (все данные из БД, переживают перезапуск):
  - всего пользователей;
  - новые: сегодня / за 7 дней / **за текущий месяц** (по `created_at`);
  - приглашено друзей (зачтённых);
  - начислено ★, выплачено ★, активные заявки;
  - выполнено заданий.
- **Заявки на вывод:** список pending с переходом в сообщение-заявку.

## 6. Партнёрская интеграция (задания-боты)

- `POST /partner/confirm` c телом `{api_key, user_id, task_id}` или
  `{api_key, user_id, sponsor_id}`.
- Партнёрские ключи хранятся в таблице `partners` и создаются в админ-панели;
  endpoint проверяет ключ по БД. Неизвестный или неактивный ключ → 403.
- Подтверждаются только ресурсы, принадлежащие этому партнёру
  (`task.partner_id == partner.id` / `sponsor.partner_id == partner.id`).
  Ресурсы без назначенного партнёра не подтверждаются.
- Проверяется, что ресурс существует, активен и имеет тип `bot`; иначе 404.
- Задание: если пользователь ещё не выполнял его — засчитать, начислить
  награду, ответ `200`. Повторный запрос идемпотентен (повторно не начисляет).
- Спонсор: пользователь должен существовать (иначе 404), после чего
  отмечается прохождение спонсора.

## 7. Конфигурация `.env`

```
BOT_TOKEN=
ADMIN_IDS=123456789,987654321
ADMIN_CHAT_ID=-1001234567890
SUPPORT_URL=https://t.me/support_username
DB_PATH=data/bot.db
PARTNER_API_HOST=0.0.0.0
PARTNER_API_PORT=8080
```

Партнёрские API-ключи не задаются в `.env`: они хранятся в таблице `partners`
и создаются/просматриваются в админ-панели.

## 8. Тестирование

- **pytest + pytest-asyncio**, in-memory SQLite.
- Сервисы тестируются напрямую, Telegram API мокается.
- Покрываемые сценарии:
  - начисление 3★ за друга ровно один раз (повторный `/start` не дублирует);
  - друг не даёт звёзд, пока не прошёл всех спонсоров;
  - баланс: начисление/списание, формат tenths;
  - вывод: нельзя выбрать подарок дороже баланса, списание при `paid`,
    идемпотентность повторного «Выплачено»;
  - гейт подписок: без спонсоров меню недоступно;
  - задания: одноразовость, «Пропустить» выдаёт другое, награда 0.5★;
  - партнёрский endpoint: неверный ключ → 403, повтор → без начисления.

## 9. Границы (вне рамок текущей версии)

- Реальная отправка Telegram-подарков автоматически (Telegram Bot API этого не
  позволяет) — выплата вручную админом.
- Антифрод сверх проверки подписок (мультиаккаунты, VPN и т.п.).
- Мультиязычность (интерфейс русский).
